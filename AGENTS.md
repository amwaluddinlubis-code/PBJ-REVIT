# Aturan Pengembangan Wajib

Aturan ini berlaku untuk semua perubahan dan kode baru di aplikasi Analisa Perencana. Stack utama adalah CodeIgniter 4.7, PHP 8.2+, MariaDB/MySQL, Tailwind CSS, IDDS, dan JavaScript browser. Ikuti pola repo yang sudah ada; aturan ini melengkapi, bukan mengganti, kontrak aplikasi.

## Cara Bekerja

- Sebelum mengubah kode, baca implementasi, pemanggil, helper, test, dan dokumentasi yang langsung terkait. Bentuk hipotesis lokal dan tentukan satu pemeriksaan yang dapat membuktikannya salah.
- Buat perubahan terkecil yang menyelesaikan kebutuhan. Jangan merapikan atau memformat ulang area yang tidak terkait.
- Pertahankan API, route, nama field, bentuk data, dan perilaku lama kecuali perubahan itu memang diminta.
- Gunakan utilitas dan komponen bersama yang sudah tersedia sebelum menambah helper, dependency, atau pola baru. Abstraksi harus mengurangi kompleksitas nyata, bukan hanya memindahkan kode.
- Jangan menganggap perubahan lokal sebagai sampah. Jangan membuang, menimpa, me-reset, atau meng-commit perubahan pengguna tanpa instruksi eksplisit.

## PHP dan CodeIgniter

- Ikuti autoload PSR-4 `App\\` di `app/`, gaya PHP file sekitar, dan API CodeIgniter 4. Jangan menambah dependency tanpa kebutuhan dan alasan yang jelas.
- Semua controller aplikasi memakai `BaseController` bila sesuai. Gunakan `tampil()` untuk halaman layout utama dan manfaatkan helper yang sudah ada seperti `sid()`, `ambilGedung()`, `hapusLunak()`, `idsTerpilih()`, serta fungsi hitung domain yang relevan.
- Controller menangani request, otorisasi, validasi, dan penyiapan data; view merender data. Jangan menaruh query database atau aturan bisnis utama di view.
- Daftarkan route privat dengan filter `auth`. Jangan memindahkan endpoint privat ke luar grup/filter untuk mempermudah pengujian atau pemanggilan.
- Ambil input dari Request CodeIgniter, validasi di server, normalisasi angka/tanggal sesuai format yang diterima aplikasi, dan gunakan `withInput()` bila alur form membutuhkannya.
- Query memakai Query Builder atau parameter binding. Jangan menyisipkan input pengguna langsung ke SQL.
- Escape output HTML dengan `esc()` sesuai konteks. Untuk data yang dimasukkan ke JavaScript, gunakan `json_encode()` dengan opsi encoding yang aman; jangan membangun kode JavaScript dari string pengguna.

## Data dan Database

- **Isolasi sekolah wajib dijaga.** Untuk data milik sekolah, gunakan sekolah aktif dari `sid()` dan sertakan `sekolah_id` pada baca, ubah, dan hapus. Jangan mempercayai `sekolah_id` dari form biasa; hanya alur tujuan-impor yang memang mendukung pilihan sekolah boleh menerimanya dan harus memvalidasinya.
- Untuk data turunan, pastikan kepemilikan melalui relasi induknya (misalnya pekerjaan melalui gedung, invoice melalui SPK). Validasi ID dan kepemilikan sebelum mengubah data.
- Gunakan soft-delete `is_deleted` / `deleted_at` dan `hapusLunak()` sesuai pola aplikasi. Jangan melakukan hard-delete pada alur bisnis biasa; pembaruan daftar aktif harus mengecualikan baris terhapus.
- Semua perubahan skema dibuat sebagai migration baru di `app/Database/Migrations/`. Jangan mengubah migration yang sudah mungkin dijalankan di instalasi pengguna. Pertahankan data, urutan migration, dan perilaku upgrade; uji pada database pengembangan yang benar.
- Operasi yang mengubah beberapa tabel atau menjaga relasi tetap konsisten harus memakai transaksi dan rollback saat gagal.
- Jangan mengubah data atau menjalankan migration terhadap database pengguna/produksi tanpa instruksi eksplisit.

## Keamanan dan Alur Data

- Setiap form POST harus menyertakan `csrf_field()` dan endpoint mutasi harus tetap terlindungi filter yang tepat.
- Validasi otorisasi dan aturan bisnis di server; atribut HTML atau JavaScript hanya membantu UX, bukan pengganti validasi.
- Untuk upload/impor, validasi ekstensi, MIME/isi, ukuran, nama/path, dan status hasil parsing. Jangan mempercayai nama file atau path dari request. Pertahankan sumber impor sesuai alur dan kebijakan aplikasi.
- Operasi massal harus membatasi ID ke sekolah dan jenis data yang benar, melewati data yang tidak berhak/terkait sesuai aturan domain, serta melaporkan hasil dengan jelas.
- Jangan mencatat atau menampilkan password, token, kredensial, isi `.env`, atau data sensitif dalam log, pesan error, maupun respons.
- Gunakan `PhpSpreadsheet` dan `Dompdf` yang sudah tersedia untuk spreadsheet dan PDF; jangan membuat parser/renderer ad hoc tanpa alasan kuat.

## Aturan UI Wajib

Sebelum mengubah tampilan, baca view, CSS, JavaScript, helper, dan dokumentasi desain yang terkait. Ikuti pola TailAdmin + token IDDS yang sudah digunakan; jangan menambah sistem visual kedua.

### Komponen View (pola TALL di CI4)

Sejak 2026-11-24 tampilan mengikuti pola komponen ala TALL tanpa mengganti framework: Tailwind + Alpine.js untuk interaksi di tempat, dan komponen server berupa partial view.

- View halaman yang panjang WAJIB dipecah menjadi partial di folder yang sama dengan nama `_<nama>.php` (mis. `bahan/_panel_upah.php`, `layout/_sidebar.php`). Halaman induk hanya merangkai partial dan menyimpan logika komponen Alpine-nya.
- Partial dirangkai dengan `$this->include('folder/_nama')`. Partial mewarisi DATA view dari controller (`tampil()`/`view()`), BUKAN variabel lokal yang dibuat di dalam berkas view induk — closure/agregat lokal yang dibutuhkan partial harus dihitung di dalam partial itu sendiri dari data controller, atau didefinisikan lokal di partial (pola `bahan/_tabel.php`).
- Argumen kedua `$this->include()` adalah opsi render CI4, bukan data — jangan memakainya untuk mengoper variabel.
- Formatter tampilan bersama tinggal di `app/Common.php` sebagai fungsi global: `tgl()`, `tglWaktu()`, `rp()` (rupiah), dan `ikonSvg()` (peta ikon SVG). Jangan menyalin closure formatter lokal baru; varian yang memang berbeda (mis. null → '—', tanpa awalan 'Rp') boleh tetap lokal di berkasnya.
- Layout utama `layout/main.php` hanya merangkai `layout/_kepala`, `_sidebar`, `_atas`, `_skrip`, dan `_modal_konfirmasi`.
- Form tambah/ubah yang isinya singkat TIDAK membuka halaman baru: tampilkan sebagai modal `mk-lapik` di halaman daftarnya (pola `spk/_modal_form.php`, `sekolah/_modal_form.php` — bidang sama persis dengan halaman formnya, POST biasa ke endpoint simpan/perbarui yang sama, data baris dioper sebagai JSON di halaman; `invoice/_modal_form.php` sudah dikonversi ke helper `form_modal()` — simpan AJAX ke `invoice/simpan` dengan id tersembunyi membedakan baru/ubah, hapus lewat `aksi_hapus`, tabel register memakai `tabel_bantu()`). Halaman form mandiri tetap dipertahankan sebagai cadangan (jalur kembali validasi & tautan langsung). Form panjang/bertab tetap halaman sendiri.
- Semua tombol SATU keluarga gaya (ala Apple) dari aturan `button, .tombol` di `public/assets/app.css`: pil penuh (radius 999px), tebal 600, bayangan halus, transisi + efek tekan `scale(.97)`. Varian hanya soal warna: utama biru IDDS, `bahaya` marun #800000, `ekspor` hijau pastel, `abu` netral. Jangan membuat kelas tombol baru dengan bentuk berbeda.
- Semua isian angka rupiah rata kanan: isian uang selalu memakai penanda `data-uang` (form_modal jenis `uang` sudah memasangnya; isian manual wajib menambahkannya) dan aturan `input[data-uang]` di `app.css` yang meratakan kanan + angka tabular. Jangan membuat isian uang tanpa `data-uang`.
- Halaman dengan banyak panel WAJIB memakai panel lipat `<details class="panel panel-lipat" data-lipat-id="...">` dengan judul panel sebagai `<summary>` (keadaan buka/tutup diingat per pengguna via localStorage oleh skrip layout). Panel yang sedang dikerjakan/utama boleh `open` sebagai bawaan; panel akar Alpine (`x-data`/`data-bulk-akar`) dan bilah alat tetap `<div class="panel">` biasa.

### Form Compact

- Form adalah alat kerja, bukan halaman penjelasan. Tampilkan field, nilai, dan aksi yang dibutuhkan tanpa paragraf pengantar panjang.
- Kelompokkan field yang saling terkait dalam grid dua kolom pada desktop dan satu kolom pada layar sempit. Pakai pola grid serta kelas form yang sudah ada.
- Jaga jarak vertikal rapat dan konsisten. Hindari panel kosong, kartu di dalam kartu, dan pembungkus dekoratif yang tidak menambah informasi.
- Gunakan label singkat di atas kontrol. Pindahkan contoh dan syarat ke hint satu baris; jangan ulangi isi label dalam placeholder.
- Tampilkan field opsional hanya bila diperlukan alur. Untuk opsi lanjutan atau jarang dipakai, gunakan `<details>` dengan judul dan ringkasan yang jelas.
- Letakkan aksi utama dekat akhir form dan bedakan secara visual dari aksi sekunder/destruktif. Hindari lebih dari satu tombol utama dalam satu konteks.
- Pertahankan `name`, `id`, `required`, nilai lama, CSRF, validasi, dan kontrak request yang sudah dipakai controller.

### Gunakan Komponen Bersama

- Pakai `.panel`, `.aksi`, token desain `--ui-*` (warna, tipografi, radius, bayangan, gerak — didefinisikan di blok "Token desain" awal `public/assets/app.css`), dark theme `html.gelap`, dan pola spacing yang sudah tersedia. **Aturan baru wajib memakai `--ui-*`**; `--ta-*`/`--fm-*` hanya alias lama dan `--ina-*` palet mentah IDDS — jangan menambah warna atau ukuran huruf literal bila token semantik tersedia. Tema gelap menukar token di `html.gelap`, bukan menambah selektor `html.gelap .komponen`. Rincian di `docs/Desain_Token.md`.
- Skala huruf hanya 7 langkah: `--ui-text-2xs` 10px (lencana/kepala tabel), `-xs` 11.5px (label, kontrol padat), `-sm` 13px (isi tabel, tombol, isian), `-base` 14.5px (teks isi, judul panel), `-lg` 17px, `-xl` 20px (judul halaman, nilai KPI), `-2xl` 24px (judul hero) — plus `-3xl` 28px dan `-display` untuk layar masuk. Pilih langkah menurut **peran**, jangan menulis `font-size: <angka>px` baru; kalau perlu ukuran lain, ubah nilai tokennya.
- Semua select tunggal otomatis menjadi searchable. Untuk placeholder khusus, pakai `data-placeholder` atau helper `select_cari()`; jangan membuat dropdown pencarian kedua. Panel dropdown select-cari dirender sebagai lapisan `fixed` di `<body>` (portal, z-index 500) agar selalu melayang di atas panel lain dan tidak pernah menambah scroll atau terpotong wadah — jangan mengembalikannya ke posisi absolute di dalam wadah. **Pengecualian:** select "Per halaman" pada paginasi tabel adalah select biasa (bukan searchable) — nilainya hanya 10/25/50/100 dan harus bisa diganti secepat mungkin tanpa membuka panel pencarian; jangan mengubahnya menjadi searchable.
- Untuk tabel, gunakan `data-cari` dan/atau `data-paginasi` agar mendapat pencarian, pengurutan, paginasi, hitungan hasil, dan empty state bersama. Jangan membuat implementasi per halaman tanpa kebutuhan yang terbukti.
- **Tabel Standar v2** (mesin bersama `paginasi.js`): setiap tabel daftar mendapat pencarian langsung, paginasi, **pengurutan klik-header** (sadar angka format Indonesia, tanggal, teks; kolom berisi kontrol formulir tidak bisa diurutkan, atau tandai `data-tanpa-urut`), **empty state** seragam saat saringan kosong, baris judul grup (satu sel `colspan` penuh atau class `baris-grup`) mengikuti baris anaknya, baris total (class `total`/`baris-total`) selalu tampil dan tidak dihitung, baris rincian (class `baris-detail`) tersinkron dengan pemiliknya, "pilih semua" hanya mencentang baris yang terlihat, dan semua baris tercetak saat print. Struktur dinormalisasi menjadi `thead`/`tbody` dengan header sticky; status tabel (kata cari, urutan, ukuran halaman, halaman) tersimpan per sesi; tombol Ekspor CSV mengunduh baris yang sedang tersaring; header urut membawa `aria-sort` dan kotak cari berlabel aksesibel. Jangan menulis ulang perilaku ini per halaman.
- **Semua tabel daftar wajib berperilaku sama**: tabel yang menampilkan daftar data (master, register, riwayat, rekap, kebutuhan) memakai perilaku bersama di atas — daftar yang bisa panjang memakai `data-paginasi`, dan setiap tabel daftar memakai `data-cari` agar selalu bisa disaring. Pengecualian hanya untuk: tabel pada halaman cetak, tabel ringkasan/pernyataan singkat (sedikit baris hitungan, mis. verifikasi anggaran dan sisa dana), sub-tabel rincian di dalam baris tabel lain, tabel editor dokumen (isi dokumen yang sedang disusun), tabel formulir per kelompok (mis. penggabungan duplikat), dan tabel yang pencariannya sudah disediakan di tingkat halaman. Di luar pengecualian itu, tabel tanpa perilaku bersama adalah ketidakselarasan yang harus diperbaiki.
- Untuk hapus massal, gunakan `komponenBulk()` dan atribut konfirmasi bersama. Jangan membuat modal konfirmasi baru untuk pola yang sudah ditangani layout.
- Pakai `<details>/<summary>` native untuk panel padat atau bagian jarang dipakai. Ringkasan harus tetap informatif saat tertutup; kelompok besar boleh tertutup awal, tetapi bagian kecil dan alur utama tetap terlihat.
- Jika nilai select diubah lewat JavaScript, dispatch event `change` atau panggil `window.perbaruiSelectCari(select)` agar label dan validasi tetap sinkron.
- Konversi satuan bahan yang berbeda antara komponen AHSP dan master memakai aturan bawaan `faktorSatuan()`; faktor manual per pasangan (bahan, satuan komponen) disimpan di tabel `bahan_konversi` lewat panel Satuan Bahan Berbeda di modul Analisa dan selalu mengalahkan aturan bawaan. Jangan menambah aturan tebak-tebakan baru di `faktorSatuan()` untuk kasus yang bisa diatur pengguna lewat faktor manual.
- Menghapus bahan dari Rencana Belanja berarti menghapus lunak komponennya di Analisa (sumber kebutuhan) — jangan menghapus master bahan atau baris SPK dari aksi itu.
- Field berisi harga/rupiah wajib memakai atribut `data-uang` (mesin bersama `uang.js`): nilai tampil dengan pemisah ribuan Indonesia saat diketik dan saat halaman dimuat, dan otomatis dikembalikan ke angka polos sebelum formulir terkirim agar parsing server tidak berubah. Gunakan `type="text"` + `inputmode="numeric"` untuk field ini — jangan `type="number"` karena tidak bisa menampilkan pemisah ribuan. Field volume/kuantitas/desimal bukan field uang dan tidak memakai pola ini.

### Kepadatan Tabel dan Panel

- Prioritaskan informasi untuk pemindaian: header jelas, angka rata kanan, kolom aksi stabil, dan teks panjang dibatasi dengan wrapping atau ellipsis yang aman.
- Jangan menyembunyikan aksi penting di dalam panel lipat. Tampilkan jumlah baris/status pada summary bila tabel dikelompokkan.
- Tabel lebar boleh memiliki scroll horizontal pada pembungkusnya; jangan membuat seluruh halaman ikut melebar.
- Hindari panel bertumpuk. Gunakan panel hanya untuk kelompok konten yang memang perlu dibatasi, bukan setiap field atau baris.

### Aksesibilitas dan Responsif

- Setiap kontrol punya label yang terlihat atau nama aksesibel; ikon aksi punya `aria-label`/tooltip bila tidak ada teks.
- Pastikan alur keyboard: fokus terlihat, Tab berurutan, Escape menutup overlay yang sesuai, dan fokus kembali ke pemicu setelah dialog ditutup.
- Modal harus memakai semantik dialog, fokus terkelola, dan tidak mengirim form sebelum konfirmasi.
- Pertahankan target sentuh sekitar 44 px pada layar sempit untuk tombol, summary, dan kontrol utama.
- Uji lebar desktop dan ponsel. Pastikan teks tidak bertumpuk, tidak terpotong tanpa cara melihatnya, dan hanya komponen yang semestinya yang menggulir.
- Periksa tema terang dan gelap; state hover, fokus, disabled, error, kosong, dan loading harus tetap terbaca.

### CSS dan Perilaku

- Scope aturan CSS dengan kelas komponen/halaman. Jangan mengubah selector global jika perubahan hanya dibutuhkan oleh satu halaman.
- Reuse fungsi/helper yang sudah ada sebelum menambahkan abstraksi baru. Hindari menggeneralisasi aturan bisnis yang berbeda hanya karena markup-nya mirip.
- Jangan mengubah struktur data, nama field, route, atau perilaku submit sebagai bagian dari perapian visual kecuali memang diminta.
- Untuk aset CSS/JavaScript yang di-cache, ikuti pola cache-busting `filemtime` pada layout.

### Jejak Halaman, Peringatan Isian & Panduan (26 Nov 2026)

- **Jejak halaman (breadcrumb)** dirender layout (`layout/_atas.php`, kelas `.remah`): diturunkan dari URI dengan peta label yang sama seperti menu sidebar, judul halaman menjadi remah terakhir (`aria-current="page"`). Modul baru WAJIB menambahkan segmennya ke peta jejak di `_atas.php` (dan sub-halaman dikenal ke peta sub) agar jejaknya benar; jangan membuat breadcrumb per halaman.
- **Peringatan perubahan belum disimpan** (skrip layout `_skrip.php`): form POST yang diubah (isian teks/area/pilihan) ditandai kotor dan memicu peringatan peramban saat berpindah halaman; tanda dibersihkan saat form dikirim. Form yang memang tidak perlu dilacak (mis. form saring POST) diberi atribut `data-tanpa-peringatan`. **Peringatan sesi**: 10 menit sebelum sesi 120 menit berakhir (dihitung sejak halaman dimuat) dialog bersama menawarkan Perpanjang Sesi lewat endpoint `sesi/sentuh` (`Auth::sentuhSesi`, hanya menyentuh sesi) — jangan menghapus endpoint ini tanpa mengganti mekanisme peringatannya.
- **Panduan dalam aplikasi** (menu Panduan Penggunaan, rute `panduan`): merender `docs/Panduan_Penggunaan.md` lewat `App\Libraries\MarkdownMini` — satu-satunya sumber isi panduan; perbarui berkas Markdown itu, bukan HTML terpisah. MarkdownMini hanya mendukung konstruksi yang dipakai panduan (judul, daftar, tabel, blok kode, kutipan, tautan aman); konstruksi baru di panduan harus didukung konverter ini dulu.

## Pengujian dan Penyelesaian

- Jalankan lint PHP untuk view/controller yang disentuh dan `node --check` untuk JavaScript yang disentuh.
- Uji perilaku utama di browser, bukan hanya keberhasilan render: buka/tutup, submit/validasi, pencarian/paginasi, dan state dinamis sesuai komponen.
- Periksa screenshot desktop dan ponsel untuk halaman yang layout-nya berubah. Uji perubahan CSS pada tema terang dan gelap bila selector terkait.
- Jalankan `composer test` untuk perubahan logika yang punya cakupan test, serta `git diff --check` sebelum selesai.
- **Pengujian database mesin uang** (`tests/Database`, sejak 24 Nov 2026): harga berjalan/AHSP, total BOQ, penomoran SPK, kunci invoice, dan `hitungPilihan` Rencana dijaga tes DatabaseTestTrait pada grup `tests` (MySQL database `pbj_test`; lihat README bagian Pengujian). Perubahan pada fungsi-fungsi itu WAJIB tetap hijau dan perilaku barunya ditambah sebagai tes. Basis tes mengatur ulang database dengan menghapus tabel + migrasi naik (bukan regress): daftar kolom koneksi CodeIgniter tersimpan di cache per proses (`BaseConnection::getFieldNames`), sehingga regress lalu migrasi naik dalam satu proses membuat penjaga `fieldExists()` membaca keadaan lama — terbukti menggagalkan backfill migrasi 000024 (`Unknown column 'bs.bap_id'`). Karena alasan yang sama, migrasi baru yang memakai penjaga `fieldExists()` + query backfill pada kolom barunya harus diperlakukan hati-hati terhadap `migrate:refresh` satu proses.
- Untuk UI, uji state normal, kosong, error, disabled, dan loading yang relevan; pastikan form tetap mengirim nilai yang sama dan validasi tetap berfungsi.
- Untuk migration atau query lintas sekolah, uji upgrade dan isolasi data pada database pengembangan yang sesuai.
- Sebutkan pemeriksaan yang benar-benar dijalankan dan hasilnya. Nyatakan jelas bila browser, test, atau database tidak tersedia.
- Jangan membuat commit, branch, push, atau stash kecuali diminta. Jangan menjalankan operasi Git destruktif; pertahankan staging dan perubahan lokal pengguna.

- **Jejak audit & gerbang peran (sejak migrasi 000015)**: aksi yang menyentuh uang dan persetujuan WAJIB dicatat dengan `catatAudit(entitas, id, aksi, keterangan)` (tabel `audit_events`) dan dibatasi peran dengan `penjagaPeran([...])` di awal method (admin selalu lolos; daftar kosong = khusus admin). Pengesahan revisi hanya ketua/kepsek/admin; jurnal pembayaran, penerimaan, bukti setor, pembayaran upah, dan transaksi kas manual hanya bendahara/admin; kosongkan modul hanya admin; impor hanya operator/admin. Invoice yang sudah memiliki jurnal pembayaran aktif TERKUNCI: tidak dapat diubah/dihapus/dikosongkan — koreksi lewat penghapusan jurnal pembayaran (tercatat di audit). Akun memiliki status `aktif` dan `harus_ganti_sandi` (akun baru & bawaan wajib ganti sandi; filter auth menegakkannya). Jangan melemahkan gerbang ini saat menambah fitur.
- **Form buat/ubah modul Analisa dan Bahan memakai modal live** (pola `.mk-lapik`/`.mk-kartu` yang sama dengan modal konfirmasi): editor komponen dibuka per baris dari modal Ubah (endpoint `komponen-ubah`) dan modal Tambah (`komponen-tambah`) — memilih bahan dari master di modal Tambah mengisi otomatis nama, satuan, dan tarif (atribut data-* pada opsi `select_cari`, tarif = harga acuan dari peta `acuanBahan` di `Analisa::detail()`; isian tetap dapat diubah, dan memilih bahan mengembalikan jenis ke Bahan), nilai koefisien × tarif terhitung langsung saat mengetik, penyimpanan lewat AJAX (balasan JSON dari `balasKomponen()` / cabang `isAJAX()`) lalu fragmen tabel & ringkasan disegarkan tanpa muat ulang halaman; faktor konversi satuan juga diatur dari modal dengan pratinjau arti faktor secara live. Jangan mengembalikan form massal sehalaman penuh untuk editor ini. Form Tambah/Ubah Bahan juga modal live di halaman Master Bahan (`bahan/simpan` & `bahan/perbarui` membalas JSON via `balasForm()` untuk AJAX dan redirect untuk form halaman; kode berikutnya dari `bahan/kode-baru`; tombol Ubah di tabel membawa data baris lewat atribut data-*). Halaman form bahan lama tetap dipertahankan untuk tautan dari modul lain.
- **Nomor SPK berikutnya dihitung dari MAX(nomor) seluruh baris termasuk yang terhapus lunak** — kunci unik `spk_sekolah_nomor (sekolah_id, nomor)` tetap dipegang baris terhapus, jadi menghitung hanya dari baris aktif menyebabkan tabrakan "duplicate entry" dan SPK gagal dibuat sesudah ada SPK yang dihapus. Berlaku di semua jalur pembuatan SPK (Register SPK, Rencana Belanja, Rencana Mingguan).

### Penggunaan Helper Tampilan (`tabel_bantu()` & `form_modal()`)

**Wajib** untuk tabel daftar dan form CRUD modal baru; sejak migrasi menyeluruh 26 Nov 2026 semua modul sudah memakai helper ini (pengecualian manual tercatat di butir helper di atas). Jangan menulis markup tabel daftar atau markup/skrip modal CRUD sendiri di luar kedua helper ini.

**`tabel_bantu(array $konfig): string`** — merender Tabel Standar v2 lengkap (`data-cari`/`data-paginasi` untuk `paginasi.js`, `baris-grup`, `baris-total`):

```php
echo tabel_bantu([
    'kolom' => [
        ['judul' => 'Nama'],
        ['judul' => 'Harga', 'angka' => true],          // 'lebar' => '110px', 'judul_html' => mentah
    ],
    'baris' => [
        ['sel' => ['Semen', ['teks' => rp(50000), 'angka' => true]]],   // string diescape
        ['sel' => [['html' => '<b>Portland</b>'], ['teks' => rp(52000), 'angka' => true]]], // 'html' mentah; sel juga terima 'class', 'colspan', 'gaya'
        ['grup' => 'Judul Grup'],                                        // baris-grup sepenuh lebar
        ['total' => [['teks' => 'Total', 'colspan' => 1], ['teks' => rp(102000), 'angka' => true]], 'class' => 'subtotal-baris'],
    ],
    'cari' => 'Cari bahan…',   // string = kotak cari aktif; false = mati
    'paginasi' => 25,          // int = baris per halaman; false = mati
    'class' => 'tabel-data',
]);
```

**`form_modal(array $konfig): string`** — merender modal CRUD (judul rata kiri di pita kepala, kaki tombol, label di border isian, validasi tooltip):

```php
<?= form_modal([
    'id' => 'modal-bahan',                          // unik per modal
    'judul' => 'Tambah Bahan', 'judul_ubah' => 'Ubah Bahan',
    'aksi' => base_url('bahan/simpan'),
    'aksi_hapus' => base_url('bahan/hapus/__ID__'), // penanda WAJIB __ID__ (bukan {id})
    'konfirmasi_hapus' => 'Hapus bahan ini?',
    'kolom' => [
        ['nama' => 'kode', 'label' => 'Kode', 'wajib' => true],
        ['nama' => 'harga', 'label' => 'Harga (Rp)', 'jenis' => 'uang', 'wajib' => true],
        ['nama' => 'jenis', 'label' => 'Jenis', 'jenis' => 'pilihan', 'opsi' => ['a' => 'A', 'b' => 'B']],
        // jenis lain: teks (bawaan) | angka | tanggal | area ('baris' => n)
        // opsi field lain: 'placeholder', 'petunjuk', 'penuh' => true (rentang 2 kolom),
        // 'saran' => [...] (datalist saran untuk field teks)
    ],
    'catatan' => 'Teks kecil di bawah field.',
    'tombol' => ['simpan_teks' => 'Simpan Bahan'],  // sakelar bawaan di bawah
]) ?>
```

- **Tombol bawaan**: Batal, Hapus, Simpan — semua tampil secara bawaan; nonaktifkan per konfig: `'tombol' => ['hapus' => false]` (atau `'batal' => false`, `'simpan' => false`). Teks Simpan per mode: `'simpan_teks'` / `'simpan_teks_ubah'`; teks Hapus: `'hapus_teks'`. Tombol Hapus hanya muncul pada mode Ubah dan hanya bila `aksi_hapus` diisi.
- **Membuka modal** (dari tombol di view): Tambah → `onclick="bukaFormModal('modal-bahan')"`; Ubah → `onclick="bukaFormModal('modal-bahan', <?= json data ?>)"` dengan data = nilai field **menurut nama field** + `'id'` baris (JSON diescape `ENT_QUOTES` seperti pola `_kelompok.php` BiayaLain). Field `uang` diisi angka polos — format ribuan diterapkan otomatis.
- **Kewajiban controller**: method simpan/hapus modul yang memakai `form_modal()` WAJIB bercabang AJAX seperti `Bahan::balasForm()` / `BiayaLain::balas()` — `isAJAX()` → `setJSON(['ok' => bool, 'pesan' => string])`; non-AJAX → redirect + flash seperti biasa. Galat validasi dikembalikan sebagai `ok=false` + pesan (tampil di dalam modal), bukan redirect.
- **Jangan** membuat modal konfirmasi baru untuk Hapus dari modal ini — helper menyerahkan Hapus ke form `data-konfirmasi` standar (`#mk-ya`).
- **Perluasan untuk modal khusus** (dipakai Analisa): `'tersembunyi' => ['komponen_id']` = input hidden tambahan yang ikut terisi data buka; `'info_html'` = HTML mentah di puncak isi modal (keterangan baris); `'catatan_html'` = HTML mentah di bawah field (pratinjau hitungan langsung); `'opsi'` pilihan boleh `['label' => ..., 'data' => [...]]` untuk atribut data-* per opsi (isian otomatis dari master); `'segarkan' => ['#wadah-x', '#ringkas-y']` = sesudah simpan berhasil, isi elemen-elemen itu diganti dari muatan segar halaman TANPA reload penuh (keadaan `open` panel `<details>` dipertahankan). Skrip modul hanya boleh menjadi JEMBATAN (mengisi keterangan/pratinjau, memanggil `bukaFormModal`) — buka/tutup/kirim/validasi tetap milik `form-modal.js`. Field `tanggal` mengikuti konvensi tanggal aplikasi (input `type=date` diubah skrip layout menjadi teks dd-mm-yyyy berkelas `isian-tanggal` + tombol kalender dan dikonversi balik ke ISO saat submit): data buka modal untuk field tanggal tetap diberikan berformat ISO yyyy-mm-dd — `form-modal.js` menampilkannya sebagai dd-mm-yyyy (perbaikan 26 Nov 2026; tanpa itu tanggal tampil mentah dan terhapus saat disimpan).
- Di `tabel_bantu()`: kolom menerima `'atribut'` (atribut th mentah, mis. `data-tanpa-urut`), sel menerima `'title'`; `'cari' => ''` berarti kotak cari aktif dengan petunjuk bawaan.
- Contoh hidup: Biaya Non-Gedung (`biayalain/_kelompok.php` + `_modal_biaya.php`), Analisa (`analisa/index.php` — 3 tabel + modal konversi; `analisa/_panel_komponen.php`, `_panel_pemakai.php`, `_modal_tambah.php`, `_modal_ubah.php` + jembatan `_skrip.php`), Register Invoice (`invoice/index.php` + `_modal_form.php`, `Invoice::balasForm`), Jurnal Pembayaran (`invoice/jurnal.php`, `Invoice::balasJurnal`), Master Bahan (`bahan/index.php` + `_modal_bahan.php`, modal memakai `segarkan`), dan modul uang (BukuKas/Setor/Upah/Penerimaan — `balasForm` per controller, penjaga Tutup Buku & pagu utuh).

Setiap halaman yang menampilkan keadaan kosong/kurang yang datanya dimiliki modul lain WAJIB memberi tautan langsung ke modul pemilik data itu — bukan sekadar menyebut nama menunya dalam teks.
